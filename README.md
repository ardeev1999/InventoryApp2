# Inventory App

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

Мобильное приложение для инвентаризации техники и мебели. 
Позволяет импортировать данные из Excel, сканировать QR-коды и штрих-коды, отслеживать статус предметов.

## Функциональность
- Импорт из .xlsx, .xls, .csv в SQLite.
- Просмотр списка предметов с фильтрацией по статусу (найден/отсутствует).
- Сканирование QR-кодов и штрих-кодов через камеру.
- Автоматическое изменение статуса при совпадении инвентарного номера.
- Отдельный список найденных предметов.

## Технологии
- Kotlin
- SQLite
- Библиотеки для работы с Excel (например, Apache POI)
- Камера и сканирование: ZXing Android Embedded 4.3.0

## Сканирование и инвентарные номера

Сканер настроен на QR, Data Matrix, Aztec, PDF417, MaxiCode, Code 128,
Code 39, Code 93, Codabar, ITF, EAN-8/13, UPC-A/E и GS1 DataBar (RSS).
Это форматы декодеров ZXing, а не гарантия чтения любого существующего
штрихкода или повреждённой этикетки; MaxiCode особенно требователен к изображению.
Для ITF дополнительно разрешены короткие номера из 2 и 4 цифр.

Результат передаётся в поиск как строка без дополнения цифрами, удаления
ведущих нулей, обрезки пробелов или преобразования в число: `1234`, `0012`
и `001234` — разные номера. Поиск в Room выполняется по точному совпадению инвентарного номера или сохранённой привязки кода.
Служебные символы формата обрабатывает декодер по правилам соответствующего стандарта.

Если генератор этикетки уже дополнил номер нулями или контрольной цифрой,
сканер не может восстановить исходный короткий номер без отдельного правила.
EAN/UPC имеют фиксированную длину; для произвольного четырёхсимвольного номера
используйте Code 128 или QR. ITF допускает только чётное количество цифр.
В импортируемом Excel храните номера как текст: числовые ячейки могут терять
ведущие нули ещё до сканирования.

## Импорт ведомостей 1С без подготовки

Загрузите исходный `.xls` или `.xlsx` через «Импорт из файла». Удалять верхние
строки не нужно. Парсер ищет заголовки «Основное средство» / «Наименование» и
«Инвентарный номер». Без заголовков поддерживаются известные схемы C/J
(название в третьем столбце, номер в десятом), A/B и прежняя A/H.
Строки без названия или номера, группировки и итоги пропускаются; первая строка
обрезанного файла сохраняется. Используется первый распознанный непустой реестр
в книге — повторяющий его второй лист не добавляется. Разные реестры на отдельных
листах следует загружать отдельными файлами.

Инвентарные номера остаются строками, включая ведущие нули, короткие номера и
буквы. Длинные номера, записанные числом и потенциально потерявшие точность Excel,
пропускаются с указанием предмета и ячейки в предварительном результате импорта.
Пользователь видит предупреждения до подтверждения записи. Текстовые длинные
номера сохраняются целиком. Временные номера для заголовков и итогов не создаются.

При загрузке доступны два режима:
- «Обновить / добавить» сохраняет предметы, отсутствующие в новой ведомости.
- «Заменить список» удаляет отсутствующие предметы. Подходит для очистки результатов
  прежнего ошибочного импорта. Выбирайте полную ведомость нужного состава имущества.

Для совпавших инвентарных номеров оба режима сохраняют статус, время сканирования,
отдел, комментарий и привязку кода. Перед записью показывается число распознанных предметов и проблемных строк.
Запись выполняется в одной транзакции только после разбора выбранного реестра
и подтверждения пользователем. При замене пропущенные строки тоже не войдут в новый список. Ошибка разбора/сохранения не заменяет базу.

## Штрихкоды 1С и QR

Ведомость остатков может содержать только инвентарный номер, а этикетка — отдельный
EAN-13. Восстановить такое соответствие по одному инвентарному номеру невозможно.
Если считанный код отсутствует в базе, приложение показывает его содержимое и
формат. Нажмите «Выбрать предмет», найдите предмет по номеру или названию и
подтвердите «Привязать и отметить». Связь сохраняется локально на устройстве;
при повторном сканировании предмет находится автоматически. Прямой поиск по
инвентарному номеру продолжает работать, в том числе для QR.

Для предмета хранится один дополнительный код в существующем поле `qrData`.
Замена прежней привязки явно отображается перед подтверждением. Код другого
предмета привязать нельзя. Сброс базы или удаление предмета удаляет его привязку;
выгрузка/перенос привязок между устройствами пока не реализованы. QR со ссылкой
или составным текстом обрабатывается как полный код, без угадывания номера внутри.

### Проверка изменений

`bash gradlew :app:testDebugUnitTest` проверяет импорт синтетических ведомостей и декодирование сгенерированных
изображений: короткие номера, ведущие нули, текст, пробелы, EAN/UPC и Codabar.
На телефоне дополнительно проверьте разрешение камеры, отмену сканирования,
поиск существующего номера и сообщение для отсутствующего. Импортируйте
`1234`, `0012` и `001234` как три отдельных предмета и убедитесь, что сканирование
каждой этикетки отмечает только соответствующий предмет.

Тест `InventoryImportTest` запускается на Android через
`bash gradlew :app:connectedDebugAndroidTest`: проверяет сохранение привязок и
статусов, замену списка, конфликты кодов и откат транзакции. Приватные ведомости
не включены в репозиторий; тест фактических файлов запускается при передаче JVM
свойства `inventory.fixtures` с локальной папкой обеих ведомостей.

Проверка предоставленных файлов: исходная ведомость — 1201 предмет и 3 предупреждения;
обрезанный `1.xls` — 1200 предметов и 3 предупреждения. В обрезанном файле
отсутствует первая запись исходной ведомости. Три предупреждения относятся к
длинным номерам в числовых ячейках; исходные цифры нужно уточнить в 1С.
