# InventoryApp 2.0

Android-приложение для инвентаризации по штрихкодам из выгрузки 1С.

## Импорт

Выберите **Импорт из файла** и исходную книгу `.xlsx` или `.xls`. Заголовки могут находиться после шапки отчёта; порядок столбцов произвольный. Используется первый лист с нужными заголовками.

| Столбец | Обработка |
| --- | --- |
| Основное средство / Наименование / Название | Название предмета; обязательно |
| Инвентарный номер | Сохраняется текстом; пустое значение отображается как «Без инвентарного номера» |
| Штрихкод | Обязательный уникальный ключ; без него строка пропускается |

Инвентарные номера могут повторяться или отсутствовать у нескольких объектов: они не являются ключами базы. Номера не обрезаются и не дополняются. Пустые ячейки `t="e"` без значения из выгрузки 1С считаются отсутствующими значениями. Настоящие ошибки Excel и небезопасные длинные числовые идентификаторы показываются в отчёте импорта; такие строки пропускаются. Длинные инвентарные номера нужно выгружать текстом.

Одинаковые повторные строки учитываются один раз; конфликт одного штрихкода у разных предметов останавливает импорт до изменения базы. Перед сохранением показываются количество записей, пропуски и ошибки. «Обновить / добавить» сохраняет остальные записи; «Заменить список» удаляет отсутствующие в импортируемом наборе. В обоих случаях отметки найденного сохраняются по штрихкоду.

Проверенный пример пользователя: 3371 строка, 3322 импортируемых предмета, 49 без штрихкода пропускаются, 195 предметов без инвентарного номера сохраняются. Пользовательский файл не включён в репозиторий.

## Сканирование и интерфейс

Результат EAN-13 или QR сравнивается **только** с полем `barcode`, соответствующим столбцу «Штрихкод». Поддерживаются также другие самостоятельные форматы ZXing. Нет поиска по инвентарному номеру, ручной привязки, усечения, дополнения или исправления контрольной цифры. UPC-A исключён из списка декодеров, чтобы EAN-13 с начальным нулём не возвращался как 12-значный UPC-A.

Повторное сканирование сообщает «Уже найден», не изменяет дату первого сканирования и не увеличивает счётчик.

На главной странице: всего / найдено / осталось; импорт, списки всех / найденных / оставшихся, сброс базы с подтверждением, экспорт, сканирование. В списках есть поиск по названию и инвентарному номеру. Пользователь видит только название и инвентарный номер; штрихкод не отображается.

Экспорт создаёт `.xlsx`: найденные, оставшиеся или оба списка на отдельных листах. В отчёте только наименование и инвентарный номер, записанные текстом. Экспорт является отчётом для пользователя, а не резервной копией для повторного импорта (в нём нет штрихкодов). Пустой список экспортируется с заголовками. Путь сохранения выбирается системным диалогом Android.

## Обновление с версии 1.0

Схема Room обновляется с версии 2 до 3 без разрушительного пересоздания базы. Старая таблица `items` сохраняется как архив, рабочая таблица `inventory_items` использует штрихкод в качестве первичного ключа. При первом запуске загрузите новый файл со штрихкодами. Старые отметки переносятся по однозначной прежней привязке либо по единственному совпадению инвентарного номера и названия. Старые номера никогда не подставляются в поле штрихкода. Сброс данных удаляет рабочий список и архив.

Модель рабочей записи: `barcode`, `name`, `inventoryNumber`, `scanned`, `scanTimestamp`. Пустой инвентарный номер хранится пустой строкой, а подпись «Без инвентарного номера» формируется для интерфейса и экспорта.

## Сборка на Windows / VS Code

Нужны JDK 17, Android SDK с platform 34 и подключённое устройство с USB-отладкой.

```powershell
git fetch origin
git switch feat/barcode-inventory-workflow
git pull --ff-only origin feat/barcode-inventory-workflow
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug
.\gradlew.bat :app:installDebug
```

Устанавливайте поверх существующей сборки, подписанной тем же ключом. Удаление приложения удаляет его базу.

## Проверки

```powershell
.\gradlew.bat :app:testDebugUnitTest
.\gradlew.bat :app:connectedDebugAndroidTest
```

JUnit проверяет импорт XLS/XLSX, пустые поля 1С, сохранение цифр, конфликты, экспорт и декодирование. Тест приватной выгрузки запускается при заданном JVM-свойстве `inventory.fixture`; файл не нужен для остальных тестов. Android-тесты проверяют Room, точный поиск по штрихкоду, независимость предметов без номера, повторное сканирование, транзакционный импорт, очистку и миграцию схемы 2 → 3. GitHub Actions собирает APK, выполняет JVM-тесты и компилирует Android-тесты; запуск Android-тестов требует устройства или эмулятора.
